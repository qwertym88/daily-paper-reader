## 摘要
在低功耗微控制器（MCU）上部署神经网络需要在内核、延迟和能量等严格约束下选择模型架构。现有工作流通常在一个或多个方面简化这一过程：使用静态代理成本（如FLOPs或参数量）、将某款MCU视为代表以及进行连续推理测试而非实际的传感调度。这些假设可能导致Pareto前沿候选排序错误、遗漏不可行部署，并模糊与调度相关的能耗。我们提出CREST（跨平台运行时评估与搜索工具），这是一个面向MCU传感系统的部署逼真的硬件在环（HIL）神经架构搜索（NAS）框架。CREST保持优化器、HIL测量边界、日志记录和重放工作流程固定，同时将工作负载、模型家族、目标后端、调度、量化和评分策略作为可配置维度。这使得部署效应在单个可重用工作流中实验性可分离。我们在三个Arm Cortex-M目标上评估了CREST的惯性里程计和音频分类任务。对于惯性里程计，基于测量能耗的HIL搜索相比基于FLOPs的选择在中位每次推理能耗上降低了41.7%，相比基于内存流量的选择降低了40.8%，且误差相似。基于FLOPs的选择还会在内存受限目标上选择不可行的部署。在STM32 N657目标上，连续推理和占空比搜索产生了不同的Pareto前沿。对于音频分类，相同的应用级策略在不同开发板上选择了不同的DS-CNN架构，而跨板重放显著改变了部署成本。总体而言，CREST表明部署逼真的MCU NAS必须联合优化模型架构、目标平台、运行时调度和部署策略，而非仅依赖静态代理成本或连续推理测量。

## Abstract
Deploying neural networks on low-power microcontrollers (MCUs) requires selecting model architectures under tight memory, latency, and energy constraints. Existing workflows often simplify this process along one or more axes: static proxy costs such as FLOPs or parameters, treating one MCU as representative, and continuous-inference tests instead of deployed sensing schedules. These assumptions can mis-rank Pareto-front candidates, miss infeasible deployments, and obscure schedule-dependent energy.   We present CREST (Cross-platform Runtime Evaluation and Search Tool), a deployment-realistic hardware-in-the-loop (HIL) neural architecture search (NAS) framework for MCU sensing systems. CREST keeps the optimizer, HIL measurement boundary, logging, and replay workflow fixed while exposing workload, model family, target backend, schedule, quantization, and scoring policy as configurable axes. This makes deployment effects experimentally separable within one reusable workflow.   We evaluate CREST on inertial odometry and audio classification across three Arm Cortex-M targets. For inertial odometry, measured-energy HIL search reduces median per-inference energy by 41.7% versus FLOPs-based selection and 40.8% versus memory-traffic-based selection at similar error. FLOPs-based selection also chooses infeasible deployments on memory-constrained targets. On the STM32 N657 target, continuous-inference and duty-cycled searches produce different Pareto frontiers. For audio classification, the same application-level policy selects different DS-CNN architectures on different boards, and cross-board replay changes deployment cost substantially.   Overall, CREST shows that deployment-realistic MCU NAS must jointly optimize model architecture, target platform, runtime schedule, and deployment policy rather than relying only on static proxy costs or continuous-inference measurements.

- **问题**：在低功耗微控制器（MCU）上部署神经网络时，现有工作流常采用三种简化假设：① 使用静态代理成本（如FLOPs、参数量、内存流量）替代实际部署成本；② 将单一MCU平台视为代表性目标；③ 仅测试连续推理模式（saturated inference）而非实际传感系统的占空比调度（duty-cycled schedule）。这些假设导致Pareto前沿候选排序错误、部署不可行、以及调度依赖的能耗被忽略。
- **含义**：部署成本不是模型架构的固有属性，而是由模型、目标平台、运行时调度、工作负载和部署策略共同决定的。现有框架将这些因素固化在一个垂直管道中，无法进行可控实验分离。因此需要一种可配置的硬件在环（HIL）NAS框架，使部署效应成为可实验分离的变量。

### 论文提出的方法论：核心思想、关键技术细节
- **核心思想**：CREST（Cross-platform Runtime Evaluation and Search Tool）是一个模块化的HIL-NAS框架，它固定优化器（Optuna）、HIL测量边界、日志记录和重放工作流，同时将以下维度暴露为可配置的轴：工作负载（workload）、模型家族（model family）、目标后端（target backend）、运行时调度（runtime schedule，连续/占空比）、量化模式（float32/int8 PTQ）、评分策略（policy）。通过这种设计，用户可以改变单一变量而保持其余部分不变，从而将部署效应归因于该变量。
- **关键技术细节**：
  - **模块化接口**：定义了数据集、任务、模型家族、目标后端等可替换接口。新增工作负载或后端只需实现对应接口，无需重写整个管道。
  - **运行时调度支持**：支持连续推理（重复推理无间隔）和占空比调度（cadenced execution，每固定周期释放一次推理，剩余时间睡眠）。占空比调度下，能耗测量覆盖完整窗口（推理 + 睡眠），而非仅活跃推理。
  - **HIL测量**：使用低成本INA228功率监测器，通过监测DUT GPIO标记来界定测量窗口，避免手动分段。支持连续和占空比两种模式的能量累积和归一化。
  - **评分策略**：支持单目标（标量分数）和多目标（Pareto前沿）。用户可定义质量-能量权衡函数。论文示例中使用了 `score = MacroF1_val - 0.10 * (E_inf / E_budget)`。
  - **重放机制**：可保存搜索日志并重新评估候选模型在不同后端/调度下的性能，实现跨条件对比。

  - **Case Study 1 (CS1)**：静态代理 vs HIL测量。对比基于FLOPs、基于内存流量（memory traffic）的Pareto搜索，以及基于实测能耗的HIL搜索。将代理搜索得到的Pareto前沿候选在目标板上重放，与HIL搜索的前沿比较。

### 实验数量与充分性
- **实验数量**：
  - **CS1**：代理搜索（FLOPs 150 trials + memory traffic 150 trials）→ 每个代理Pareto前沿候选23个（FLOPs）和12个（memory traffic）→ 在4个后端上重放，共约92+48个重放测量，其中76+47个有效。HIL搜索：5个后端×150或250 trials，共约~1050次HIL测量。

  - **CS3**：每个后端最多300 trials，获取200个可行算分候选。总约600 trials。敏感度分析：12个budget和12个penalty设置。
- **充分性评价**：实验覆盖了两种传感任务、三个不同架构的MCU、两种运行时调度、静态代理与测量能耗对比、单目标与多目标优化。实验设计系统且控制了多种变量，结论有充分数据支持。然而，仅使用了int8 PTQ和float32两种量化方式，未涉及更高量级量化（如int4）或其他任务（如图像、KWS），硬件平台有限（仅Cortex-M系列，未涵盖RISC-V或其他MCU架构）。

### 论文的主要结论与发现
1. **静态代理不可靠**：FLOPs和内存流量代理在4个后端上大多数被测量能耗HIL搜索的Pareto前沿支配（49/55和37/42），且FLOPs导致部分候选因内存不足而不可执行。HIL搜索降低中值能量41.7%和40.8%（与FLOPs和内存流量对比）。
2. **运行时调度改变最优选择**：连续推理搜索出来的Pareto前沿在占空比调度下全部被占空比搜索的前沿支配（9/9），且能量节省2.1%每窗口；反过来，占空比搜索的前沿在连续推理下支配了9/11的连续搜索前沿，节省44.1%活跃能量。说明调度必须作为搜索参数，而非仅作为后处理。
3. **应用级评分选择目标依赖**：相同音频评分函数在不同板上选择了不同架构（Portenta选择紧凑型、STM32选择宽型）。跨板重放导致能量和延迟显著增加（STM32模型在Portenta上能量增加4.1×）。
4. **结论**：MCU NAS必须联合优化模型架构、目标平台、运行时调度和部署策略，而不能仅依赖静态代理或连续推理测量。

### 优点
- **模块化与可分离性**：CREST通过固定搜索循环和测量边界，将部署效应变为可独立调整的轴，使得不同实验之间结果差异可以归因于单一变量，而非管道差异。
- **低成本HIL测量**：使用$15的INA228和简单MCU工装，实现了每候选能量、延迟的精确测量（变异系数<1%），且支持连续和占空比两种模式。
- **调度感知NAS**：首次将运行时调度作为搜索时的可配置变量，而不仅仅是报告指标。
- **开放和可复现**：代码开源，工作流程可重复，支持添加新任务、模型、后端。
- **重放机制**：允许解耦搜索和评估，便于跨条件对比。

### 不足与局限
- **实验覆盖有限**：仅两个任务（惯性里程计和音频分类），仅Cortex-M系列MCU，未涵盖RISC-V或其他常见MCU架构。量化仅包含float32和int8 PTQ，未探索int4、混合精度或量化感知训练。
- **缺少大规模消融**：未对不同优化器（如Bayesian vs GA）、不同训练预算、不同搜索空间大小进行消融实验。
- **能耗模型简化**：占空比下仅考虑了推理+睡眠两阶段，未包含传感器采样、特征提取、通信等真实传感流水线的其他阶段（论文承认这是设计选择，可后续扩展）。
- **缺乏对搜索策略本身的比较**：仅使用Optuna默认的TPE和NSGA-II，未与其他NAS方法（如进化、贝叶斯优化变种）对比。
- **可扩展性挑战**：HIL测量硬件设置需要手动接线、配置，对大规模分布式搜索可能不友好；论文提到每个板子需17–35小时，相比纯模拟方法耗时较长。
- **未讨论多任务/多模型同时部署场景**：仅针对单一模型搜索。
