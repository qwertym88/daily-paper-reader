## 摘要
在移动机器人上部署数十亿参数的视觉-语言-动作（VLA）策略引发了一个系统冲突：语义推理受益于云端GPU，而闭环控制必须在网络延迟和抖动的情况下本地响应。现有的分层和异步策略提高了吞吐量，但其慢路径表征仍可能过期到达，或需要显式调度和延迟提示。我们引入了CloudEdgeVLA，一种将时间错位视为表征学习问题的云边策略。云端VLA将延迟观测编码为缓慢变化的任务特征，而轻量级边缘头将最新可用的云特征与当前局部视觉相结合。在训练期间，当前帧和随机延迟帧在新鲜路径和过时路径中与相同的当前动作目标配对。这一目标鼓励云端表征保留任务级信息，同时边缘路径提供状态敏感修正。在四个LIBERO套件中，CloudEdgeVLA在40步均匀延迟窗口下保留了63.8%–78.0%的成功率，而VLASH最高仅为6.4%，所评估的单路径基线最高仅为3.0%。通过从控制回路中消除阻塞同步，该设计为可扩展的VLA部署提供了一条实用途径，其中云模型可以增长，而边缘计算保持轻量级和响应迅速。

## Abstract
Deploying billion-parameter Vision-Language-Action (VLA) policies on mobile robots creates a systems conflict: semantic reasoning benefits from cloud GPUs, whereas closed-loop control must respond locally despite network delay and jitter. Existing hierarchical and asynchronous policies improve throughput, but their slow-path representations can still arrive stale or require explicit scheduling and delay cues. We introduce CloudEdgeVLA, a cloud-edge policy that treats temporal misalignment as a representation-learning problem. A cloud VLA encodes delayed observations into slowly varying task features, while a lightweight edge head combines the latest available cloud feature with current local vision. During training, current and randomly delayed frames are paired with the same current action target in fresh and stale paths. This objective encourages the cloud representation to preserve task-level information while the edge path supplies state-sensitive corrections. Across four LIBERO suites, CloudEdgeVLA retains 63.8--78.0% success with a 40-step uniform-delay window, whereas VLASH reaches at most 6.4% and the evaluated single-path baselines at most 3.0%. By removing blocking synchronization from the control loop, the design offers a practical route to scalable VLA deployment in which cloud models can grow while edge computation remains lightweight and responsive.

# CloudEdgeVLA 论文详细中文总结

## 1. 核心问题与整体含义（研究动机与背景）

**核心矛盾：** 视觉-语言-动作（VLA）模型（如 RT-2、OpenVLA、π0、Octo）在语义推理与语言指令跟随方面能力强大，但其数十亿参数规模使得模型难以部署在功率和重量受限的移动机器人本体上。云端卸载可以解决算力问题，却引入了通信延迟、抖动与丢包等新的系统挑战：云端特征返回时，其对应输入图像描述的场景可能已经过期，而机器人必须基于过期的语义特征执行当前动作。

**现有方案的不足：**

- 阻塞等待云特征 → 降低控制频率；
- 非阻塞执行但直接使用最新可用特征 → 引入时间错配；
- 已有异步方案（如 MResT、DP-VLA、HiRT、SmolVLA）虽然实现了快慢系统解耦，但仍依赖显式调度、延迟提示或动作块回放，未真正解决"表示本身随延迟老化"的问题；
- VLASH 通过未来状态感知展开预测来补偿延迟，但在延迟窗口较大时依然崩溃。

**论文的核心立场：** 将时间错位重构成一个**表示学习问题**，而非纯推理调度问题。通过训练使云端表征对时间不敏感（携带"做什么"的任务级信息），由边缘表征负责"现在怎么做"的状态级信息，从而**从根本上限定了哪些决策依赖于过时信息**。

## 2. 方法论

### 2.1 核心思想

受双系统理论（System 1 / System 2）启发，设计一个**非阻塞的云边协作接口**：

- **云端（System 2）**：大模型 VLA 骨干，编码"任务目标、操作策略、物体语义"等**随时间缓慢变化**的特征；
- **边缘（System 1 感知+控制）**：轻量视觉编码器提取**当前**视觉特征，由动作头融合云端特征与当前视觉，输出精确动作。

### 2.2 系统架构

- **云端 VLA 骨干 fθ**：基于预训练 VLM（OpenVLA 7B）用 LoRA 适配，运行于云端，输出规划特征 h = fθ(o, ℓ) ∈ R^{L×D}（L = T×A 为动作块维度）。
- **边缘视觉编码器 vψ**：SigLIP-Base（冻结），从当前观测 ot 提取实时视觉特征 zt = vψ(ot)。
- **边缘动作头 gϕ**：对云端特征沿动作维度均值池化、投影视觉特征到同构空间、拼接后经残差 MLP 预测连续动作块 ât = gϕ(h_{t−k}, zt) ∈ R^{T×A}。

### 2.3 配对帧双路径训练（Paired-Frame Dual-Path Training）

**关键训练策略：** 在训练中采样窗口 W 内当前帧 ot 与随机延迟帧 o_{t−d}（d ~ Uniform(1, W−1)），分别经云端骨干得到 h_fresh 与 h_stale，再与**相同的当前视觉特征 zt** 融合、以**相同的动作目标 at** 监督：

- **损失函数：** L = (1−λ)‖â_fresh − at‖₁ + λ‖â_stale − at‖₁
- **课程学习：** λ 从 0 逐步升至 λ_max，先让骨干学习强表征，再施加延迟不变性压力。
- h_stale 不截断梯度，两条路径都更新骨干。

**机制直觉：** 在随机延迟 d 下，与瞬时状态强绑定的特征无法可靠预测 at，而任务身份、目标、粗略进度等稳定信息保持有用，从而**涌现**出对时间位移的表征特化（不依赖显式不变性损失）。

### 2.4 部署协议

完全异步、无阻塞：边缘采集 ot → 异步发送云端 → 云端返回最近的 h（可能对应旧帧）→ 边缘计算 zt → 融合输出 ât → 执行。**从不阻塞等待特定云响应**。

- CloudEdgeVLA（本文方法）。

### 3.3 评估条件

**充分性较好：**

## 6. 主要结论

1. **延迟鲁棒性远超基线：** dmax=40 时，CloudEdgeVLA 维持在 63.8%–78.0%（按套件），而 VLASH 最高 6.4%、单路径基线最高 3.0%。
2. **延迟保留曲线：** 归一化延迟 AUC 达 90.8%（VLASH 仅 32.4%）；同步成功率保留率 76.5%（VLASH 为 1.8%）。
3. **套件差异：** Goal 套件最稳定（40 步仅降 18.5 点），Long 下降最多（27.9 点），但最差情况下仍比最强基线高 63.3 点。
4. **机制定位：** d=20 时，骨干表征漂移（Dh）降低 59.2%，延迟传递增益（κ）降低 72.7%，组合将动作漂移降低 88.9%、演示 MAE 降低 88.5%——鲁棒性来自骨干稳定性 + 头部衰减的**协同效果**。
5. **反事实结论：** 当前边缘视觉的直接"救援"作用极小（0.03%），鲁棒性主要由云端的时不变特征和头部对残余漂移的衰减提供；但边缘视觉仍是必要前提（去掉后从 95.1% 跌至 31.6%）。

## 7. 优点

- **问题重构新颖：** 将延迟容忍当作可学习的表示属性，而非纯推理调度问题，接口设计（非阻塞、无时钟同步、无延迟元数据）简洁实用；
- **训练方法优雅且高效：** 通过配对帧 + 同一动作目标的双路径监督实现涌现式表征特化，无需显式不变性损失、域自适应或对抗训练；
- **训练-部署的一致性：** 训练时模拟的随机延迟与部署时的任意网络延迟分布对齐策略需求；
- **消融设计到位：** 不仅证明整体有效性，还量化定位了每个组件的贡献；
- **机制诊断深入且诚实：** 使用固定偏移离线探头 + 反事实审计，区分"骨干稳定"与"头部衰减"的独立贡献，并主动报告了"边缘直接修复作用极小"这一不利证据；
- **实验覆盖完整：** 从闭环成功率、消融、逐任务一致性、动作块时空分解到真实机器人初步验证，多层级证据链完整。

## 8. 不足与局限

- **延迟范围有限：** 仅在均匀延迟窗口内验证，**未测试无限延迟、长时断连或超出训练分布的延迟**；作者明确承认"不意味对无界延迟或云端断连的容忍"，需时间戳特征 + 本地回退策略配合；
- **真实实验统计功效不足：** 仅 10 trials/变体，结果属描述性证据；未验证嵌入式设备效率或宽泛硬件泛化；
- **训练成本偏高：** 每个样本需两次云端骨干前向（fresh + stale 路径），训练计算量显著增加；
- **感知维度受限：** 冻结的 RGB 编码器缺少深度、力觉、触觉等模态，对接触敏感任务可能不够；
- **机制宣称的边界：** 反事实审计表明 120k 检查点上"当前边缘视觉直接修复过时云特征"的作用几乎为零，端到端鲁棒性主要来自云端稳定性 + 头部衰减，这与论文标题中"边缘头结合当前视觉"的直觉性表述存在张力——边缘视觉的重要作用更多是**必要前提**而非**直接修正**；
- **对照公平性细节：** 离线机制诊断中比较的 OpenVLA-OFT 与 CloudEdgeVLA checkpoint 在架构和训练目标上均不同（系统级比较，非孤立组件隔离）；延迟以环境步计算，不能直接解释为硬件无关的毫秒延迟；
- **云端断连问题未解决：** timestamped 特征与本地回退策略仍是实际产品化部署的必要补充，论文未实现。

CloudEdgeVLA 的核心贡献在于**将 VLA 云边部署中的延迟容忍问题从调度层下沉到表示学习层**，通过配对帧双路径训练实现云端表征的时不变特化与边缘的实时视觉接地。实验证据充分证明了其在长延迟窗口下的显著优势，机制的消融与反事实审计也使结论更加可信。该工作为云模型持续增大而边缘保持轻量响应的可扩展机器人部署提供了有价值的系统设计方案。
