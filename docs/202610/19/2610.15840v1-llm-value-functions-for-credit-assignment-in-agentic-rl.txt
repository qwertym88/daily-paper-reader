# LLM Value Functions for Credit Assignment in Agentic RL 

Kaijie Zhu ∗, Weixiang Yan , Omar Attia , Abbas Kazerouni , Alexander Toshev , Andrew Szot 

Apple Reinforcement learning (RL) for large language model (LLM) agents remains challenging in long-horizon tasks with sparse outcome rewards, where assigning credit to individual actions is difficult. Methods such as GRPO assign the same trajectory-level advantage to all actions, while critic-based methods require learning an additional value function that can be costly and unstable. We introduce LLM Value Function RL (LVRL), which uses the pretrained knowledge and in-context learning ability of an LLM to estimate policy-aware state values without finetuning a separate critic. LVRL con-ditions the value model on group context and calibrates its predictions using known values at the initial and terminal states, enabling step-level credit assignment from estimated value differences. We further extend this idea to learning from an expert policy through on-policy distillation (OPD), introducing LLM Value Function OPD (LVOPD), which focuses teacher supervision on actions associated with decreases in estimated value. We evaluate our approach across diverse agentic benchmarks: AppWorld, BabyAI, and SWE-bench Verified. Across policy scales (4B to 32B), LVRL consistently and sub-stantially outperforms both GRPO and PPO. On AppWorld and SWE-bench Verified, LVRL yields absolute improvements of up to 13 .6 and 8.6 percentage points over GRPO. Notably, on tasks requiring extended exploration like BabyAI, LVRL raises success from near 0% to 75 .0% . Furthermore, LVOPD yields consistent improvements over standard distillation baselines on AppWorld. Finally, a Monte-Carlo analysis shows that the frozen critic identifies most semantic pitfalls and recoveries, indicating that LVRL extracts meaningful, policy-aware step-level credit from sparse terminal outcomes.

## 1 Introduction 

Language models are increasingly deployed as agents that reason and act over many steps to solve complex tasks (Yao et al., 2022; Yang et al., 2024; Jimenez et al., 2024; Trivedi et al., 2024). Reinforcement learning allows these agents to improve from experience, but environment rewards are typically sparse and outcome-based in the form of a single binary signal at the end of the episode indicating success or failure. How to distribute this single bit of feedback across individual actions is the classical problem of temporal credit assignment (Sutton & Barto, 1998). Current policy optimization methods face a trade-off between coarse trajectory-level credit and the high cost of learning a value function. Outcome-only methods like GRPO (Shao et al., 2024) estimate a group-relative baseline and assign the same scalar advantage to every action in a trajectory. This uniform signal fails to distinguish individual contributions as mistakes in successful trajectories receive positive credit, while useful actions in failed trajectories receive negative credit. Alternatively, methods like PPO (Schulman et al., 2017) learn a value function to estimate step-level advantages. However, training a critic adds computational overhead and struggles to accurately evaluate long interaction histories from sparse rewards (Kazemnejad et al., 2025). While recent work explores alternative step-level credit mechanisms, such as process reward

To overcome these limitations, we introduce LLM Value Function RL (LVRL), a method that extracts dense, per-step credit using a strong, frozen LLM as a value critic. By evaluating completed trajectories in hindsight, the frozen LLM critic observes downstream consequences to accurately assess earlier actions, such as ignored tool errors or successful recoveries. Because value estimation depends on the acting policy, we make the frozen LLM policy-aware through in-context learning. Specifically, we condition the estimator on summaries of other rollouts from the same task, along with their empirical success rate and final rewards. This dynamically updates the critic’s context with the current policy’s behavior and task performance, without requiring any parameter updates. We then convert the predicted values into step-level advantages via consecutive value differences (Ng et al., 1999). Crucially, by anchoring the initial state to the group success rate and the terminal state to the observed final reward, we guarantee that these step-level advantages sum exactly to the trajectory’s overall group-relative return. The frozen critic thus redistributes sparse outcome rewards across individual actions. We further extend this credit assignment technique to on-policy distillation (OPD), where a stronger teacher provides token-level supervision (Agarwal et al., 2024; Gu et al., 2024). Since uniform distillation penalizes large KL divergence everywhere, it can suppress alternative yet successful strategies discovered by the student. To align distillation with the capabilities of the student, LVOPD introduces value-guided gating . By restricting teacher supervision to actions that decrease the estimated value, we selectively correct execution errors while preserving the student’s independent progress. We train and evaluate LVRL and LVOPD on AppWorld, BabyAI, and SWE-bench Verified across policy scales ranging from 4B to 32B parameters. In LVRL, we utilize Claude Opus 4.6 as the frozen LLM value critic. LVRL consistently improves final generalization over outcome-only supervision (GRPO) and learned value functions (PPO). For instance, on Qwen3-8B, LVRL achieves 26 .3% success on AppWorld and 20 .2% on SWE-bench Verified, compared to 19 .8% and 12 .0% for GRPO, respectively. Notably, LVRL is particularly critical in environments requiring extended exploration: on BabyAI, it reaches 65 .5% success on out-of-distribution scenarios, whereas baseline methods fail entirely. Furthermore, LVOPD yields consistent improvements over standard distillation baselines on AppWorld, reaching a 20 .2% success rate with Qwen3-4B and improving pure OPD by 3.2 percentage points. Finally, we analyze the accuracy of the frozen LLM critic’s value predictions. Using Monte-Carlo rollouts as a ground-truth probe, we demonstrate that predicted value changes correctly identify 72 % of critical pitfalls and 66 % of recoveries. Furthermore, our ablations highlight two insights: in-context policy calibration is important for maximizing improvements, and the method’s overall efficacy is bounded by the capability of the chosen LLM critic. In summary, we present a unified framework for leveraging a frozen, policy-aware LLM to provide per-action credit assignment to guide RL and on-policy distillation, all without critic updates. 

## 2 Related Work 

Step-level credit assignment for LLM agents. Classical actor–critic methods address temporal credit assignment by learning a parameterized value function (Schulman et al., 2015, 2017), an approach extended to multi-turn language agents by ArCHer (Zhou et al., 2024) and GenAC (Shan et al., 2026). To avoid the overhead of critic optimization, recent methods explore alternative credit mechanisms. The GRPO family of algorithms (Shao et al., 2024; Liu et al., 2025; Yu et al., 2025) relies on group-relative trajectory returns, uniformly assigning the same advantage to all actions within a rollout. Another line of work relies on extensive Monte-Carlo sampling; VinePPO (Kazemnejad et al., 2025) explicitly rolls out continuations from intermediate states to estimate state values, whereas GiGPO (Feng et al., 2025) and SALT (Li et al., 2026a) achieve a similar effect implicitly by aggregating returns over shared states across multiple trajectories. Other approaches rely on auxiliary models or proxy signals. Process reward models are trained with interme-diate supervision (Lightman et al., 2024; Zhou et al., 2025; Wang et al., 2025b; Xi et al., 2026; Wu et al., 2026), while implicit estimators derive step- or token-level credit from hindsight judgments of the policy LLM (Tan et al., 2026), target-answer likelihoods (Wang et al., 2025a; Tao et al., 2026; Oh et al., 2026), or internal 21 Group rollout

Since these implicit estimators are tailored for single-turn reasoning with static answers, adapting them to multi-turn agentic tasks would require non-trivial modifications to handle dynamic environment feedback, complicating direct comparisons. On-policy distillation. Knowledge distillation transfers capabilities from a stronger teacher to a student model (Hinton et al., 2015). For generative tasks, on-policy distillation (OPD) mitigates exposure bias by evaluating the teacher on prefixes generated by the student (Agarwal et al., 2024), often optimizing a reverse-KL objective (Gu et al., 2024). However, standard token-level distillation is overly rigid, penalizing deviation from the teacher even when the student discovers a valid alternative strategy. Recent methods adapt teacher-guided updates using token- or step-level likelihood differences (Jia et al., 2026; Zhong et al., 2026), verifier rewards combined with teacher signals (Akhondzadeh et al., 2026; Yang et al., 2026; Xu et al., 2026; Lin et al., 2026), or environment-informed teacher signals (Zhou et al., 2026; Li et al., 2026b). SAGE-OPD explicitly allows valid alternative actions to skip supervision (Zhou et al., 2026), while FutureBridge-OPD validates candidate teacher interventions through student continuations scored using teacher-relative preferences (Chen et al., 2026). These approaches typically rely on specialized heuristics or complex combinations of environment and teacher signals to define their gating rules. Our approach, LVOPD, offers a unified and streamlined alternative: it weights reverse-KL distillation by the negative part of consecutive value differences estimated by the frozen LLM critic. Actions with non-negative predicted value changes therefore receive no distillation loss, preserving the student’s valid alternative strategies even when they differ from the teacher’s preferred behavior. 33 Method

3.2 LLM Value Function RL 

LLM Value Function RL (LVRL) uses a frozen LLM to estimate state values from completed trajectories and converts these estimates into step-level advantages without requiring critic updates. The overall pipeline is illustrated in Figure 1. The core of our approach lies in utilizing the frozen LLM, denoted as Vϕ, to generate step-level value estimates. For each task, we sample a group of trajectories G = {τ1, . . . , τ G} from the current policy and compute their mean return μG. For each target trajectory τi, we randomly select k other trajectories from G as context. A single query then jointly estimates all interior state values as Vϕ(si,t | τi, {S(τj )}j∈C i , μ G), where Ci ⊆{1, . . . , G } \ { i} with |C i| = k indexes the context trajectories. To reduce context length, the summarization function S(·) condenses each context rollout into its essential action–observation history (see Appendix C). We anchor the endpoints to empirical data: the initial state to the group success rate ( Vϕ(si, 0) = μG) and the terminal state to the observed final reward ( Vϕ(si,T i ) = R(τi)). Inspired by potential-based shaping (Ng et al., 1999), we define the unnormalized step-level advantage as 

Ai,t = Vϕ(si,t +1 ) − Vϕ(si,t ). Since intermediate environment rewards are zero, setting γ = 1 makes this formulation mathematically equivalent to Generalized Advantage Estimation (GAE) at λ = 0 . However, Vϕ

is conditioned on the completed trajectory and its outcome, so it is a hindsight estimate rather than a true state-value function. Let σstep denote the standard deviation of these unnormalized advantages across all valid environment steps in the entire rollout group G, computed over the set {Aj,t | j ∈ { 1, . . . , G }, 0 ≤ t < T j }.We compute the final normalized step advantage as Ai,t = Ai,t /σ step . LVRL then replaces the learned advantage ˆAt in Equation (3.1) with our normalized step-level advantage Ai,t . While Ai,t is computed at the environment-step level, the policy generates each action ai,t as a sequence of tokens. Therefore, all tokens within ai,t inherit the exact same Ai,t , whereas the likelihood ratio and clipping are evaluated per-token. The final policy loss LLVRL (θ; B) is the negative empirical mean of this token-level surrogate across the minibatch. Estimator error is strictly confined to within-trajectory credit assignment and cannot flip the sign of a trajectory’s overall advantage. 

3.3 LLM Value Function OPD 

LVRL uses the step-level advantage to determine how sampled behavior contributes to the policy update. When a stronger teacher model with accessible token distributions is available, this same advantage can serve a complementary role: determining where teacher supervision should be applied. We refer to this joint setting as LLM Value Function OPD (LVOPD). Standard OPD trains the student on its own generated prefixes by minimizing the divergence against token-level targets from a frozen teacher πE . However, applying this supervision uniformly throughout a trajectory is problematic. A large KL divergence does not necessarily imply that the student’s behavior is incorrect; the student might be employing a different, yet effective, reasoning strategy or surface form (e.g., exploring a software repository in a different but valid order). Forcing the student to match the teacher everywhere can suppress alternative behaviors that contribute to task success. The step-level advantage from Section 3.2 provides a principled mechanism to disentangle task failure from benign divergence. When Ai,t ≥ 0, the sampled action is estimated to contribute positively or neutrally to the outcome. In this scenario, distillation is either redundant (if the student and teacher align) or potentially counterproductive (if they diverge), as uniform supervision risks penalizing the student’s valid alternative strategies. Conversely, when Ai,t < 0, the action reduces the estimated task value. On these steps, the RL policy gradient merely pushes the policy away from the mistake, whereas distillation supplies a stronger reference distribution to guide the student toward a correct recovery path. Consequently, teacher supervision is most critical on steps with negative advantages, motivating our selective gating mechanism. We implement this value-guided distillation by using the step-level advantage to gate the reverse-KL objective. ## 4 Experiments 

4.1 Setup 

Benchmark environments. We train and evaluate on three multi-step agent environments spanning dis-tinct capabilities: digital tool use, spatial navigation, and repository-level software engineering. AppWorld 

(Trivedi et al., 2024) requires an agent to complete everyday digital tasks by writing and executing code against a suite of simulated applications. We train on the 90 tasks of the AppWorld training tasks. BabyAI (Chevalier-Boisvert et al., 2018) provides text navigation and interaction tasks in a grid world. To rigorously test sus-tained multi-step decision-making, we use a modified Pickup benchmark arranged in a 2 × 3 grid of six rooms. This topology requires the agent to navigate across rooms and open doors to pick up a target object. We train on 285 grid configurations with randomized object positions and target door distances in {1, 2, 3}. The 5policy receives textual egocentric observations and emits one low-level action per step, such as move forward or turn left. R2E-Gym (Jain et al., 2025) provides repository-level software-engineering tasks in which the agent interacts with the codebase through the four tools of the R2E-Gym scaffold ( search , file_editor ,

execute_bash , and finish ). We use 3, 200 R2E-Gym tasks and the R2E-Gym agent scaffold for training. All three environments provide sparse outcome rewards, with task success determined at the end of each trajectory. Full details about these training environments and the following evaluation environments are in Appendix A. 

Training protocol and baselines. We fine-tune Qwen3-4B and Qwen3-8B on AppWorld and BabyAI, and Qwen3-8B and Qwen3-32B on R2E-Gym (Yang et al., 2025). All policies operate in non-thinking mode to isolate the effect of RL optimization. We run three training seeds on AppWorld and BabyAI and one seed on R2E-Gym due to the higher computational cost of this environment. All methods use a group size of G = 8 .Full training details are in Appendix B. For LVRL, we compare against GRPO, which estimates advantages without learning a value function, and PPO, which learns a parameterized value function for advantage estimation. We use Claude Opus 4.6 (An-thropic, 2026) as the frozen LLM value critic with three in-context examples. The estimated API costs per trajectory for each environment are summarized in Appendix B.1. For LVOPD, we mainly focus our evaluation on AppWorld, comparing against two distillation baselines to isolate the impact of step-level gating. Pure OPD applies teacher supervision uniformly across all generated tokens. Trajectory-gated OPD replaces both components of LVOPD with their trajectory-level counterparts: it optimizes the GRPO objective and gates the same reverse-KL loss with the GRPO advantage. Consequently, it applies a single supervision weight to every step of a rollout. For our LVOPD implementation, Qwen3-235B-A22B-Thinking-2507-FP8 (Qwen3-235B for brevity) serves as both the distillation teacher and the frozen LLM value critic, with the distillation strength set to β = 1 .

Evaluation protocol. We evaluate AppWorld policies on the Test Challenge split and R2E-Gym policies on SWE-bench Verified (Jimenez et al., 2024). For BabyAI, we evaluate on 300 in-distribution layouts (door distances ∈ { 1, 2, 3}) and 200 out-of-distribution layouts (distances ∈ { 4, 5}). For all environments, we evaluate the final training checkpoint in three independent runs. For AppWorld and BabyAI, we report the mean and standard deviation across the three training seeds. For R2E-Gym, we report the mean and standard deviation across the three evaluation runs of the single seed. 

4.2 Does LVRL Improve Long-Horizon Agent Learning? 

We evaluate whether LVRL translates to superior generalization on held-out tasks. As shown in Table 1, LVRL consistently outperforms GRPO and PPO across all domains and model scales. On AppWorld, LVRL achieves a success rate of 24 .3% with Qwen3-4B and 26 .3% with Qwen3-8B. This substantially exceeds the strongest baselines at each scale, which achieve only 14 .8% (PPO) and 19 .8% (GRPO), respectively. This performance gap is sustained in the repository-level SWE-bench Verified environment. For Qwen3-8B, LVRL reaches 20 .2% , substantially exceeding GRPO ( 12 .0% ) and PPO ( 9.0% ). Furthermore, scaling the policy to Qwen3-32B increases LVRL’s performance to 30 .9% , outperforming PPO’s 24 .9% . This demonstrates that LVRL remains highly effective even for large-capacity models. Beyond final performance, LVRL significantly improves overall learning efficiency. As illustrated in Figure 9, LVRL establishes an early lead in training reward and converges much faster across these environments. In contrast, GRPO struggles with slower convergence, and PPO requires substantially more environment interactions to learn a useful critic. This suggests that our step-level value guidance improves sample efficiency. The advantage of step-level credit assignment is most pronounced in the BabyAI setting. Because the base models’ success rates are near 0% , initial rollouts yield almost exclusively zero rewards. This creates a severe cold-start bottleneck: GRPO advantages vanish without reward variance, and PPO’s learned critic collapses to predicting zero everywhere. Consequently, both baselines fail to extract meaningful learning signals, scoring near 0% on both in-distribution (ID) and out-of-distribution (OOD) layouts. For LVRL, when all trajectories in a group fail, both endpoint anchors are zero, so the unnormalized advantages sum to zero for every trajectory. Nevertheless, interior estimates can vary, producing positive and negative step advantages. To understand these gains qualitatively, we analyze the step-level credit assigned by LVRL across environ-ments. Unlike GRPO, whose relative advantages vanish entirely if all rollouts in a group fail, the frozen LLM critic in LVRL can still isolate useful intermediate progress. For instance, it assigns positive value differences to constructive steps, such as recovering from API parameter errors in AppWorld, opening a door to reveal a target in BabyAI, or successfully reproducing a bug in R2E-Gym, even when these trajectories ultimately fail. Importantly, our framework is not tied to a single proprietary API. As shown in our ablations (Section 4.5), alternative strong models like GLM-5.2 can also yield competitive policy improvements. Distilling this signal into a smaller, more efficient local critic is a promising direction for reducing this cost. 

4.3 Does LVOPD Improve On-Policy Distillation? 

We evaluate whether the step-level advantages produced by our frozen LLM value critic improve on-policy distillation. As established in Section 4.1, the three evaluated methods form a progression in signal granularity. Pure OPD relies entirely on teacher supervision without environment reward. Trajectory-gated OPD adds a GRPO policy loss and uses its trajectory-level advantage to gate distillation. LVOPD finally resolves both the policy-gradient signal and the gate to the step level. As shown in Table 2, LVOPD yields consistent improvements over standard distillation baselines on AppWorld. For Qwen3-4B, LVOPD achieves 20 .2% success, outperforming both Pure OPD ( 17 .0% ) and Trajectory-gated OPD ( 19 .2% ). A similar trend is observed for Qwen3-8B, where LVOPD reaches 23 .3% , compared to 22 .2% 

for Pure OPD and 21 .2% for Trajectory-gated OPD. These results indicate that step-level gating provides a more reliable distillation signal than uniform or trajectory-level approaches. This generalization advantage is closely aligned with the observed training dynamics. As illustrated in Figure 10, while pure OPD exhibits rapid initial learning, LVOPD surpasses it after approximately 100 training steps and achieves the highest final training reward across both model scales. This pattern suggests that although uniform distillation provides dense early guidance, it eventually restricts the student’s policy space. By selectively gating supervision, LVOPD avoids this plateau and continues to optimize based on valid student exploration. Despite these gains, the efficacy of value-guided distillation is limited by the capability of the chosen LLM value critic. On BabyAI, all OPD variants, including LVOPD, completely fail to generalize, yielding success rates near 0% (Appendix E). The failure of pure OPD indicates that token-level supervision from Qwen3-235B alone is insufficient for BabyAI. 4.4 Validating Step-Level Value Signals 

To validate the accuracy of the frozen LLM critic, we evaluate whether its predicted step-level value differences align with true changes in the probability of trajectory success. Because environments like AppWorld lack step-level, policy-dependent value annotations, we construct reference labels using extensive Monte-Carlo (MC) rollouts. We use three checkpoints from a single AppWorld training run, taken at approximately 25% , 50% , and 75% 

of training to cover the early, middle, and late stages. For each checkpoint we randomly select 30 tasks and sample one successful and one failed trajectory per task under that checkpoint, giving 180 trajectories with 

3,899 states in total. For each recorded state st, we replay the original action prefix and sample M = 32 

independent continuations from the same checkpoint. The fraction that succeed is our Monte-Carlo value estimate V MC (st), and ∆MC  

> t

= V MC (st+1 ) − V MC (st) measures the change across a transition. We label a transition a pitfall when ∆MC  

> t

≤ − 3σ and a recovery when ∆MC  

> t

≥ 3σ, where σ = 0 .125 is the largest possible standard deviation of the difference between two independent estimates at M = 32 as detailed in Appendix F.2. Transitions with |∆MC  

> t

| < σ are MC-neutral : their estimated change is indistinguishable from sampling noise. This yields 76 pitfalls, 38 recoveries, and 1,533 MC-neutral transitions. For evaluation, let ∆pred  

> t

= Vϕ(st+1 ) − Vϕ(st) denote the predicted value difference. The group-level normal-ization (Section 3.2) used during training divides this difference by a positive constant and therefore preserves its sign. Thus, we consider a step t to be a predicted pitfall when ∆pred  

> t

< 0 and a predicted recovery when 

∆pred  

> t

> 0. Our analysis reveals that the predicted value change has the same sign as the Monte-Carlo change for 72% of pitfalls and 66% of recoveries. In comparison, it decreases on only 8% of MC-neutral transitions and increases on 22% . These substantial margins provide strong empirical evidence that the frozen LLM critic extracts meaningful, step-level outcome signals rather than random noise. We further compare LVRL against a rule-based error-marker baseline for pitfall detection. This baseline labels a transition as a pitfall simply if the environment output contains text such as Traceback , Execution failed , or No code available to execute . The baseline detects only 13% of the MC pitfalls and flags 3% 

of the MC-neutral transitions. This demonstrates that explicit execution failures alone cannot fully account for the pitfall detection achieved by our predicted value signal. As illustrated in Appendix F.4.2, a step may produce an API error yet establish the correct task logic. The value model correctly identifies such decisions as positive progress, distinguishing the trajectory from other failed rollouts. To understand where the remaining errors occur, we group the 114 Monte-Carlo events into ten bins by their position in the trajectory. As shown in Figure 11, agreement generally increases later in a trajectory. As a coarse summary, the sign-agreement rate increases from 44% in the first third to 78% in the middle third and 

88% in the final third. In particular, the model assigns no value change to 29% of early events, compared with only 4% of late events, indicating that it often fails to react to events early in a trajectory. This pattern suggests that the predicted signal becomes more reliable as the trajectory progresses. We further analyze these early actions where the critic and the Monte-Carlo estimates diverged. Early disagreements frequently happen in useful preparatory actions, such as inspecting API documentation, logging in, or retrieving task 8data. In 12 out of 19 early disagreements, the LLM critic interprets the action as semantic progress and either maintains or increases its value prediction, whereas the empirical MC value actually decreases. This pattern suggests that the frozen LLM critic’s value estimates are not strictly on-policy. While it correctly identifies useful semantic progress, it overestimates the current student’s ability to successfully complete the task. 

4.5 Ablation Studies 

In-context calibration of the frozen LLM critic. Our LLM critic uses information from the rollout group to calibrate its value estimates to the current policy. The group success rate μG and final reward 

R(τi) anchor the initial-state and terminal-state values, respectively, while summaries of k randomly sampled rollouts {S(τj )}j∈C i provide same-task examples from the current policy. Because these components jointly ground the critic’s expectations in empirical outcomes, we ablate them together by providing only the current trajectory τi to the critic and removing the endpoint anchors. As shown in Table 3, removing this calibration context reduces the AppWorld success rate from 26 .3% to 22 .1% .While this ablated variant still outperforms the standard GRPO baseline ( 19 .8% ), the full method achieves the highest mean success rate, confirming the utility of in-context calibration. Although separating the effect of the endpoint anchors from that of the context rollouts, and varying the number of context rollouts, is left to future work, we hypothesize that performance improves with context size. Specifically, incorporating more context rollouts should yield a richer, more accurate representation of the current policy, thereby further enhancing the critic’s value estimation. 

Choice of the frozen LLM critic. We evaluate how the underlying capability of the frozen LLM critic impacts downstream policy learning. Using LVRL, we train Qwen3-4B on AppWorld with different models as the frozen LLM value critic: Qwen3-235B, GLM-5.2 (Zeng et al., 2026), and Claude Opus 4.6. All other training settings are fixed, and we train three independent seeds per critic. As shown in Table 4, while all evaluated critics successfully improve upon the base model’s 4.2% success rate, the magnitude of this improvement depends strongly on the critic’s capability. For instance, using Qwen3-235B as the critic yields a modest success rate of 9.8% . In contrast, substituting it with more capable models dramatically unlocks the student’s learning potential, reaching 22 .3% with GLM-5.2 and 24 .3% with Claude Opus 4.6. This gap shows that the effectiveness of step-level credit assignment is bottlenecked by the capability of the frozen critic, and it supports our explanation of the LVOPD results on BabyAI in Section 4.3, where Qwen3-235B serves as the critic. Furthermore, the comparably high performance of GLM-5.2 and Claude Opus 4.6 suggests that LVRL generalizes across different frontier model families. 

## 5 Conclusion and Discussion 

This work introduces LLM Value Function RL (LVRL), a method for dense credit assignment in LLM agent reinforcement learning. Instead of training a separate value model, LVRL uses a frozen LLM to estimate the value of intermediate states in a completed trajectory. It makes these estimates policy-aware by conditioning the LLM on rollout statistics from the current policy via in-context learning. By anchoring the initial and terminal values to the group success rate and the actual environment outcome, the consecutive value differences telescope to the group-relative return. This process safely redistributes the actual reward across individual steps, providing an advantage signal that distinguishes progress, mistakes, and recoveries without additional environment interactions. We also introduce LLM Value Function OPD (LVOPD), which reuses this step-level advantage to gate on-policy distillation, directing teacher supervision strictly to actions that decrease the estimated value. Across agent environments spanning tool use, software engineering, and spatial navigation, LVRL outperforms GRPO and PPO baselines, while LVOPD improves upon uniform and trajectory-gated distillation baselines. Despite these strong results, our approach has several limitations. First, the method heavily relies on the capability of the frozen LLM critic to judge task progress. As shown in our experiments, a weaker critic yields substantially smaller downstream gains. For instance, our LVOPD experiments relied on Qwen3-235B as both the teacher and critic. Evaluating LVOPD with a stronger critic, such as Claude Opus 4.6, could potentially unlock much higher distillation performance, which we leave to future work. Second, LVRL 9introduces additional inference overhead. Querying a large LLM to predict step values for every trajectory during training can be prohibitive when training throughput or compute budget is constrained. Future work can investigate reducing this cost, for example, by querying the estimator only when its value signal is highly uncertain or by distilling its step-level knowledge into a smaller, learned critic. Finally, we designed LVRL specifically for multi-turn agentic environments, where interactions decompose naturally into textual steps. Extending this step-level credit assignment to non-agentic RL domains, such as mathematical reasoning, remains an open and promising direction.

## A Environment and Task Details 

A.1 AppWorld  

> Environment.

AppWorld (Trivedi et al., 2024) is a high-fidelity simulator of a personal digital environment in which the agent acts on behalf of a simulated user by writing Python against nine day-to-day applications (amazon , file_system , gmail , phone , simple_note , splitwise , spotify , todoist , venmo ) exposed through documented APIs. Two meta-applications complete the interface: api_docs , which the agent queries to discover apps, list their APIs, and retrieve individual specifications, and supervisor , which holds the user’s profile, account credentials, and the complete_task call that terminates an episode. The agent must discover the relevant APIs through api_docs , authenticate by retrieving credentials from supervisor , and only then compose the calls that satisfy the instruction.  

> Task splits.

Policy optimization uses only the 90 -task train split ( 30 scenarios × 3 variants). We report final performance on test_challenge (417 tasks), whose scenarios are disjoint from those in train . 

> Agent interface.

Each episode is a multi-turn conversation over a stateful Python REPL. On every turn the policy emits free-form reasoning followed by a single fenced Python code block; the environment ex-ecutes that block in a session that persists across turns, so variables, imports, and access tokens carry over. It returns either the captured standard output, an Execution successful. acknowledgement, or the Python traceback on error, with a 30 -second timeout per block. An episode ends when the agent calls 

apis.supervisor.complete_task() , passing answer=<value> for question-answering tasks and no argu-ment for state-changing ones, or when the turn budget is exhausted. Figure 2 shows an example.  

> Instruction prompt.

We use the same prompt for both training and evaluation: a static preamble introducing the three api_docs discovery calls, a 14 -turn demonstration dialogue on one Spotify task, and an eight-item instruction list (e.g., close every code block; reuse variables across turns; inspect an API specification before calling it; write one small code block per turn; page through paginated APIs via page_index ; call 

complete_task when done).  

> Reward.

Reward is sparse, binary, and awarded only at the end of an episode. When the agent calls 

complete_task , or when the turn budget runs out, AppWorld runs its own validation suite against the resulting database state, and we set r = 1 if and only if that suite passes in full. There is no intermediate shaping and no partial credit: the fraction of validation tests passed is logged for analysis but never enters the reward. Calling complete_task is not sufficient for success: an episode that declares completion while the validation suite fails receives zero reward, and this is by far the most common failure mode we observe.  

> Evaluation configuration.

At evaluation the trained policy is served with vLLM through an OpenAI-compatible endpoint, with the same prompt, action format, and binary success criterion as training. We sample at temperature 0.6 and take 3 rollouts per task, reporting pass@1 over all 417 test_challenge tasks. Two budgets are relaxed relative to training: the turn cap is 70 , and the context cap is 40 k tokens. The path crosses one, three, and five doors respectively, which is what door distance measures. Every layout holds the same inventory of 18 objects, so distractor identities carry no information and only the spatial arrangement and the choice of target vary. The agent never observes this map: it receives a textual egocentric description (Figure 4). 

Agent interface. The policy interacts with BabyAI entirely through text. At each turn, the agent receives a text description of its 7×7 egocentric view; the view covers the cells ahead of and beside the agent but nothing behind it, and walls block vision. The agent then emits a short reasoning statement followed by exactly one primitive action in an <action> tag, chosen from left , right , forward , pick , drop , and toggle .Figure 4 gives the protocol and an abridged successful episode. 

Reward. Reward is sparse and binary: the agent receives r = 1 on the step where it picks up the target object and r = 0 on every other step. An episode terminates as soon as success is detected, or when the step budget is exhausted, whichever comes first. Picking up a wrong object neither terminates the episode nor yields reward: the instruction is verified against the object currently carried, so the agent must drop 

the wrong object before it can pick up another. A turn whose reply contains no parseable <action> tag is executed as a no-op. It still consumes one step of the budget and is recorded in the dialogue history with an explicit “no valid action found” message. 

Evaluation configuration. We evaluate policies on two held-out sets: an in-distribution (ID) set and an out-of-distribution (OOD) set, defined relative to the door distances used during training. The training layouts have door distances in {1, 2, 3}. The ID set contains 300 layouts, with 100 at each of these three distances, and tests generalization to unseen spatial configurations within the training distance range. The training, ID, and OOD splits use disjoint seed ranges and share no layouts. The OOD set contains 200 layouts, with 100 each at door distances 4 and 5. Neither distance appears in training, so solving these tasks requires navigating across more doors than in the training tasks. A.3 R2E-Gym and SWE-bench Verified 

Environment. R2E-Gym (Jain et al., 2025) is a collection of executable software-engineering environments procedurally curated from real Python repositories. Each instance provides a natural-language issue report and a Docker image containing the repository snapshot at the corresponding commit, with the project and its dependencies pre-installed under /testbed ; the agent’s task is to edit the repository so that the issue is resolved. The scaffold exposes the sandbox through four tools: 16 • search (grep-style lookup over a file or directory), • file_editor (view files with line numbers or a condensed skeleton, and create , str_replace , insert ,

undo_edit edits), • execute_bash (run a shell command in the container), • finish (declare the episode complete). The agent must localize the fault from the issue text alone, edit the source, and typically write and run its own reproduction script to check the fix; each instance also ships with an execution-based test suite that is used only for reward and is never visible to the policy.  

> Task splits.

Policy optimization uses 3,200 executable instances from the R2E-Gym-Subset training pool, whose repositories are disjoint from those in SWE-bench Verified (Jain et al., 2025). We report final perfor-mance on SWE-bench Verified (Jimenez et al., 2024), the 500 -task human-validated subset of SWE-bench, which shares the same instance format (issue plus containerized repository) and therefore plugs into the same scaffold unchanged; since its repositories never appear in training, it measures transfer to unseen codebases rather than memorization.  

> Agent interface.

Each episode runs in a fresh container started from the instance’s image. On every turn the policy emits free-form reasoning followed by exactly one tool call in Hermes format, a <tool_call> tag wrapping a JSON object with the tool name and arguments; the tool schemas are injected once into the system message through the model’s chat template. The environment executes the call with a 90 -second timeout and returns the tool output as the next user message. A turn without a parseable tool call executes nothing: the agent receives a fixed corrective message and the turn still counts against the budget. Only the first call in a turn is executed. Per-turn generation is capped at 4,096 tokens, and the episode ends when the agent calls finish or after 50 turns. Figure 5 shows an example.  

> Instruction prompt.

We use the R2E-Gym (Jain et al., 2025) function-calling prompt unchanged for both training and evaluation: a one-sentence system message framing the agent as a programming assistant for issue resolution, and an instance message that embeds the issue inside <github_issue> tags followed by a fixed list of workflow tips (explore the repository first; write a reproduce_issue.py script with a timeout and run it to confirm the error; edit only non-test files; rerun the script after the fix; consider edge cases; every response must contain a function call).  

> Reward.

Reward is sparse, binary, and computed only at the end of an episode. When the agent calls finish ,or when the turn budget is exhausted, the harness runs the instance’s held-out fail-to-pass and pass-to-pass tests against the final repository state (with a 500 -second timeout), and r = 1 if and only if the full suite passes.  

> Evaluation configuration.

At evaluation the trained policy is served with vLLM, and our harness is the same as in training: the same prompt, tool schemas, Hermes action format, observation packing, and context truncation, with thinking mode disabled for the Qwen3 backbone. The configuration is 50 turns, 4,096 

tokens per turn, temperature 1.0, top-p 1.0. For Qwen3-32B, the context length is 64k, while for Qwen3-8B, we maintain 32k. 18 B Training Details 

B.1 Cost of Value Estimation 

We estimate token usage from the full logged prompts and responses, using the cl100k_base tokenizer as a proxy because API token usage was not retained. Each query jointly estimates all state values for one target trajectory. At Claude Opus 4.6’s standard rates of $ 5 and $ 25 per million input and output tokens, respectively, the estimated cost per trajectory is $ 0.061 –$ 0.062 for AppWorld, $ 0.107 for BabyAI, and $ 0.140 

for R2E-Gym. These estimates exclude separate trajectory-summarization calls and do not apply caching or batch discounts. We use the same model for rollout summarization and value prediction. For example, in LVRL, Claude Opus 4.6 is used in both cases. The summarization cost per trajectory is similar to that of value estimation, as their input and output token counts are similar. 

B.2 LVRL  

> Student policies.

We initialize the student policies from the released Qwen3-4B, Qwen3-8B, and Qwen3-32B checkpoints and fine-tune all model parameters. The policies operate in non-thinking mode during both training and evaluation. AppWorld and BabyAI experiments use Qwen3-4B and Qwen3-8B, whereas R2E-Gym experiments use Qwen3-8B and Qwen3-32B. For each environment–model pair, GRPO, PPO, and LVRL use the same initial checkpoint, task-sampling procedure, rollout budget, number of optimization updates, and generation configuration.  

> Rollout and optimization budget.

For AppWorld and BabyAI, training uses 64 parallel environments across eight GPUs, with eight environments per GPU. At each update, the 64 trajectories are organized into eight rollout groups of size G = 8 . The trajectories within each group correspond to the same task and initial state. AppWorld, BabyAI, and R2E-Gym are trained for 500 , 150 , and 100 updates, respectively. The same budgets are used for GRPO, PPO, and LVRL.  

> PPO critic.

Our PPO baseline adds a DeepCriticHead to the student LM. The critic is a four-layer MLP with hidden width 2,048 , implemented in bfloat16 and attached to the LM hidden states. The policy and critic share the entire LM backbone. They are trained jointly using the same optimizer and backward pass, and gradients from the value loss update the shared backbone. We use γ = 1 .0 and λ = 0 .95 for GAE. Advantages are normalized before policy optimization. The value loss is a clipped mean-squared error between the predicted values and return targets, with coefficient 0.5. The critic architecture and hyperparameters are held fixed across the three environments. GRPO uses the same rollout groups and policy-optimization configuration but does not train a critic.  

> Checkpoint selection and evaluation.

For all environments, we evaluate the final saved checkpoint of each training run, defined as the checkpoint with the largest training-update index. Each selected checkpoint is evaluated in three independent stochastic evaluation runs. For AppWorld and BabyAI, each reported seed result is the average of its three evaluation runs, and we report the mean and standard deviation across three independently trained seeds. For R2E-Gym, we train one seed and report the mean and standard deviation across its three evaluation runs.

These results suggest that the value model is more conservative early in a trajectory and becomes more responsive as the trajectory progresses. We also examine several task-level properties. The opposite-sign rate is 12% on Easy tasks ( n = 25 ), 16% 

on Medium tasks ( n = 70 ), and 11% on Hard tasks ( n = 19 ). It is similarly stable when tasks are divided by reference-solution length: 13% for solutions with at most 40 lines and 16% for longer solutions. Other stratifications, including the number of apps and whether the task requires a returned answer, produce smaller differences over limited subgroups. We therefore do not find evidence that standard measures of task difficulty explain the position-dependent pattern. Trajectory position is only a coarse proxy for how far an action is from its observable consequences. The results are consistent with long-range attribution being more difficult, but do not establish it as the cause. The qualitative examples below illustrate both the local evidence the value model uses successfully and the downstream effects it can miss.
