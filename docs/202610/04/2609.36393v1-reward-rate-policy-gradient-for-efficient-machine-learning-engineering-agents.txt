ABSTRACT 

Traditional reinforcement learning (RL) techniques focus on maximizing expected cumulative reward, where each action assumes to take a constant unit of time. However, this assumption does not hold for agentic RL tasks such as machine learning engineering (MLE) agents, where actions involve data loading, feature engineering, and model training that take variable durations. Efficiency matters in modern agentic RL where actions are costly. To address this limitation, we adapt from continuous-time RL and Semi-Markov Decision Process (SMDP) for-mulation and propose Reward-rate Policy Gradient (RPG), where we focus on optimizing the reward rate — the long-term reward per unit of time. RPG esti-mates the reward rate from off-policy samples, then charges each action for the time it consumes at that rate. We first conduct theoretical analysis in the bandit setting to establish that RPG approximates the optimal reward rate and empiri-cally demonstrate it outperforms baselines while avoiding enumeration over the policy space, a known issue for an existing method. We then further apply RPG on a small language model (Qwen3.5-4B) with self-improvement loops and em-pirically show it obtains higher rewards within a fixed time budget than vanilla RL on MLE-Bench and NanoGPT, with a 19.2% and 85.7% margin, respectively. Our method provides a practical solution for optimizing performance under wait time considerations in modern agentic RL tasks, where actions interact with external environments and cost time. 

1 INTRODUCTION 

RL has been used extensively to train language models (LMs) and agents, where the standard ap-proach is to maximize expected cumulative reward (Christiano et al., 2017; Zhang et al., 2025a). Recently, there has been interest in MLE agents, where the goal is to automate the MLE pipeline to achieve best performance on held-out data (Chan et al., 2025; Yang et al., 2025; Nam et al., 2026). Current approaches mostly apply a strong LM in a search procedure: AIDE explores the space of candidate programs as a tree (Jiang et al., 2025), while MLE-STAR retrieves an initial solution with a search engine and then refines its targeted components (Nam et al., 2026). A separate line trains the model itself with RL on performance score (Yang et al., 2025). However, none of these methods perform gradient updates that fundamentally change agents’ behavior to learn to generate more effi-cient solutions. In MLE, each action takes variable time and resources, so it is important to consider samples’ costs for practicality — we want agents that are not only good, but also efficient .One solution is to use multi-objective RL and search for the Pareto frontier between performance and time (Roijers et al., 2013; Hayes et al., 2022), but computing the set of optimal solutions is often infeasible and compute-heavy (Hayes et al., 2022). These limitations motivate an objective that 

intrinsically aims for long-run efficiency. One natural formulation is the long-run reward per unit of time studied in Semi-Markov Decision Process (SMDP) (Sutton et al., 1999b; Das et al., 1999; György et al., 2007). Intuitively, the method uses RL to maximize relative rewards, calculated from total rewards minus the amount that it would have earned if time were spent optimally. Existing approaches mainly use two ways to tackle this. Directly optimizing the reward rate with SMDP policy gradient objective (Sutton et al., 1999a) requires estimating the rate of the current policy from on-policy rollouts, an operation that is still expensive when actions are costly. The continuous-time bandit approach (György et al., 2007) estimates the optimal reward rate from historical samples, but it requires an exhaustive search over the policy space, infeasible in modern agentic RL settings where action space is large. To that end, we propose Reward-rate Policy Gradient (RPG), which uses off-policy historical sam-ples to estimate the reward rate under the greedy policy and maximizes for relative reward (Figure 1). RPG avoids the limitations of the two previous methods. It does not need time-costly on-policy roll-outs for each gradient step, and does not require searching over the policy space. Additionally, RPG is simple to adopt in the current RL pipeline, since it only requires a reward-rate estimator and uses the relative reward as the learning signal. We first study RPG in the bandit setting and theoreti-cally prove that, in expectation, if the greedy policy’s reward rate is estimated well, then RPG is equivalent to the Dinkelbach iteration (Dinkelbach, 1967; Schaible, 1976), and natural policy gra-dient (NPG) (Amari, 1998) is suited for reward-rate optimization due to preconditioning on Fisher information. Experiments on the bandit setting confirm that RPG obtains lower regret than the reward-rate upper-confidence-bound algorithm by György et al. (2007) without the need to search over the policy space. These findings motivate us to apply Proximal Policy Optimization (PPO), a first-order approximation of NPG methods (Kakade, 2001; Schulman et al., 2015), on MLE-Bench and NanoGPT. Compared against vanilla RL baselines on the same time budget, RPG shows a 19.2% average improvement in performance across 20 out of 22 MLE-Bench tasks and an 85.7% margin on NanoGPT. Our findings demonstrate that RPG is a practical solution for future agentic RL frameworks where actions are costly.

Current limitations. We first describe limitations of current approaches and then share the intu-ition behind our algorithm design. The SMDP policy gradient theorem in Equation (2) tells us it is viable to do gradient-based optimization on a parameterized policy to maximize reward rate. How-ever, the core constraint in practice is that it requires multiple rollouts of the on-policy trajectory 

{(rj , δ j )}Tj=1 to estimate ρ(π). Since the time δj for each step is variable and costly, this makes the estimation take a long time, at least P 

> j≤T

δj , for each gradient update, making it impractical for training efficient MLE agents. On the other hand, the continuous-time bandit approach is an alterna-tive by optimizing for the relative reward using an off-policy reward rate estimate ˆρt (Equation (7)), but the limitation being that it involves enumeration over all possible policies. 

Proposed algorithm. Given the limitations discussed above, our design principle for creating a practical reward-rate RL algorithm is as follows. We first use a predictor fρ fitted on the historical buffer B to approximate the reward rate and use the predicted rate ˆρ to calculate relative reward ˜r.This design allows us to avoid sampling on-policy long-horizon rollouts. Unlike the continuous-time bandit setting where policies are deterministic (György et al., 2007), LMs have stochastic policies, so we apply policy gradient updates on expected relative reward to train LMs agents. Our algorithm is shown in Algorithm 1. Ideally, the reward-rate predictor fρ should approximate the optimal ρ∗,which then serves as ˆρ for the relative reward. However, directly estimating ˆρ ≈ ρ∗ is difficult, even in the bandit setting, since it requires enumeration over the policy space. Thus, to make the approach practical, we set fρ to estimate the greedy policy’s reward rate. This choice is supported by our results in the bandit setting (Sections 3.2 and 3.3), where we demonstrate that a softmax policy with NPG updates converges to the optimal ρ∗ through both theory and experiments. Empirically on MLE-Bench and NanoGPT, we show that PPO also performs well despite it being a first-order approximation of NPG. The estimator fρ can be anything that estimates the greedy reward rate, such as Bayesian inference, Robbins-Monro iteration, or neural networks. 3.2 THEORETICAL ANALYSIS

State transition with self-improvement. Besides setting up the environment and reward properly, we also want our agent to improve based on its own previous attempts, so we would ideally have a self-improving agent making progress on the task over time. We discuss how we connect the agent’s own solutions to form self-improvement loops. At every step, we store the observed transition 

(at, r t+1 , δ t+1 ) into the buffer B. The next state st+1 is constructed by concatenating the base prompt s0 with the previous code a′ and a self-improvement phrase i0 explicitly asking the agent to improve upon the performance score r′ and time δ′. The selection of (a′, r ′, δ ′) from buffer B is based on a top-k selection according to the relative reward ˜r(ˆ ρt+1 ) = r′ − ˆρt+1 δ′. This naturally gives a self-improvement chain where the agent is tasked with making progress on its best proposed solutions observed thus far. 

Reward-rate predictor. At each step t, our agent uses its history of attempts to predict the reward rate ˆρ. The reward-rate estimator fρ is a NIW posterior with joint Gaussian likelihood (Murphy, 2012) fitted from historical samples observed in buffer B. We fit the posterior at each step, and sample M reward rates from it and take the 95th percentile ˆρt+1 = Quantile 0.95 ({ρm}Mm=1 ). 5 RELATED WORK 

Machine learning engineering agents. Many works currently ask whether an agent can carry out machine learning engineering tasks in an end-to-end fashion (Nam et al., 2026; Tang et al., 2023; Chan et al., 2025; Li et al., 2024; Zhang et al., 2026; Qiang et al., 2026). Similar lines of work also include using agents on data science tasks such as data preprocessing and hyperparameter tuning (Grosnit et al., 2024; Bendinelli et al., 2025; Zhang et al., 2023; Liu et al., 2024). Most agentic approaches in these tasks involve scaffolding a frozen model, such as by searching the solution space as a tree (Jiang et al., 2025), which do not train MLE-specific experience into the model weights. One of the closest works to ours is by Yang et al. (2025), who trained a small LM with RL on MLE-Bench and observed that actions take a variable amount of time, but the focus was on mitigating the time bias favoring faster solutions in asynchronous RL updates. By contrast, our work directly treats time as a cost term in the RL objective using the SMDP reward-rate formulation and trains agents to learn to take efficient actions. 

Reward-rate RL. We acknowledge that the reward-rate objective itself is classical. The SMDP formulation provides the theoretical framework for our method (Sutton et al., 1999b), and the continuous-time bandit (György et al., 2007) gives the idea of using off-policy estimates for the optimal reward rate. Similar problems also appear in renewal processes with bandit feedback (Cayci et al., 2019) where the objective is to maximize reward within a fixed horizon. A core mathemati-cal toolkit is Dinkelbach iteration for fractional programming (Dinkelbach, 1967; Schaible, 1976), where all of these works aforementioned rely on it to transform a ratio objective into a sequence of linear ones. Budgeted and knapsack bandits (Badanidiyuru et al., 2013; Ding et al., 2013; Xia et al., 2016) also consider actions with costs, but they enforce a hard constraint on a finite budget. In RL for LMs literature, the environment is episodic with actions assumed to have a constant cost (Schul-man et al., 2017; DeepSeek-AI et al., 2025). A survey on agentic RL with LMs (Zhang et al., 2025a) also uses the same formulation, with no notion of how long an action can take. Guan et al. (2025) trades off latency against cost, but requires exploring the Pareto frontier in a multi-agent framework. To our knowledge, no existing work applies reward-rate RL in modern LM agents. 

Self-improvement. Performing self-improvement by asking an agent to revise its own previous attempts is a well-established pattern, such as critiquing its outputs directly (Madaan et al., 2023), reflecting on feedback from the environment (Shinn et al., 2023), training on the attempts that hap-pened to succeed (Zelikman et al., 2022), and rewriting the scaffolding (Zelikman et al., 2023). The idea of self-improvement loops has also been explored in discovery tasks (Yuksekgonul et al., 2026). Closer to our setting, the loop can be driven by execution feedback, where a model repairs its own program from the error message that the program produced (Chen et al., 2023). The loop can also be used on an agent archive to create a tree of diverse and capable agents through evolutionary search (Zhang et al., 2025b). Zeng et al. (2025) proposes using a balance score for the exploration-exploitation trade-off and updating models on samples that are above a score threshold. Our work focuses on using self-improving loops as state transitions to train agents. 

6 CONCLUSION 

We proposed a practical reward-rate RL algorithm, namely RPG, for training efficient MLE agents using the SMDP formulation, where each action takes variable time, and the objective is long-run reward per unit of time. RPG uses greedy policy’s reward rate estimates for the relative reward calcu-lation and directly maximizes it through PPO. It avoids enumeration over all policies and time-costly on-policy rollouts, two limitations for directly applying the SMDP methods in practice. Through the-oretical analysis, simulation experiments, and empirical experiments on MLE-Bench and NanoGPT, we demonstrated that RPG produces an agent policy that learns to take actions efficiently and max-imizes reward. There are some limitations in this work. The scope of the empirical experiments is focused on MLE tasks, but other agentic RL tasks where actions cost variable time exist, so it would be interesting to see how reward-rate RL does on these tasks. C.3.1 ENVIRONMENT , R EWARD AND SELF -IMPROVEMENT 

Execution. Every action a is a code block generated by the policy (Qwen3.5-4B). The code block is executed in its own sandbox subprocess environment with its own working directory, under a memory budget of 16GB and a compute budget of 2 CPUs. The subprocess is killed when it reaches timeout δmax . We set δmax = 600 seconds, except for nomad2018, pizza, tabular-2021 and tabular-2022, where the dataset is large enough that 600 seconds admits almost no honest attempt, so we use δmax = 1200 seconds for these tasks. Time δ is floored at clip_time = 0 .1 seconds before it is used anywhere, so that no sample can claim an unboundedly large rate. We train with a batch size of 128. Thus, assuming full parallelization at each step, we require 16 ×128 = 2048GB of memory with 256 CPUs. This amount of resource is large in academic setting, so we use a first-in-first-out queue that processes the 128 samples by 16 samples running parallel at a time through Ray. 

Reward. A run is a valid submission when the script terminates before δmax , generates a submis-sion file, and that file is accepted by the MLE-Bench grader. The grader returns the competition’s own metric. For the 15 tasks whose metric is higher-is-better and bounded, we use performance metric (such as AUC) directly as the reward. Outcomes. A crash, a parse failure, or a timeout with no usable validation line is an invalid at-tempt. Implementer. A train_gpt.py used for self-improvement prompts is around 560 lines. Ask-ing the policy (Qwen3.5-4B) to generate such scripts would use a lot of response tokens, slow down training, and the majority of the focus would be on correct code transcription. To alleviate this issue, we ask the policy to propose a change specification in three fixed sections: DIAGNOSIS , CHANGE ,and RISK . For each section, it needs to point out the corresponding snippet in the parent code block to be improved upon. The implementer is GPT 5.6 Terra at temperature 0 with a 16 ,384 -token budget, and it is given the parent script, the change specification, and asked for creating a search-and-replace edit blocks. The edit blocks then go through regular expression to replace the parent code with the new edits, which we call the output script as patch . A reply by the implementer is accepted only if every edit block matches the parent exactly and the validation logging lines remain untouched (to prevent model from hacking the validation logs).
